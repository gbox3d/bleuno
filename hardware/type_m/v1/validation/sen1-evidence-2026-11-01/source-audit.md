# SENSOR1 / SEN1 연결 상태의 독립 확인

2026-11-01. **보존된 EasyEDA 원본과 현재 KiCad 파일에서 SEN1 신호는 센서 커넥터 2번과 10kΩ 저항 2번에만 연결되어 있다. MCU의 어떤 패드에도 직접 이어지지 않는다.** 이는 저장된 설계의 연결 상태에 대한 결론이다. 설계자의 의도나 실제 제작 보드의 연결 상태를 이 결과만으로 단정하지 않는다.

## 확인한 자료

- [원본 `.epro`](../../source/MovingTarget_MotorConT1_2026-10-31.epro): ZIP 내부 JSON을 직접 읽었다. SHA-256 `AD53D548A11A0D6652DB9E8F0933E21C97D479A1E3235C9C981F93750B959BDA`.
- [현재 KiCad PCB](../../kicad/type_m_v1.kicad_pcb): 설치된 `pcbnew`로 실제 구리 도형을 읽었다. net 이름이 달라도 서로 닿는지 검사했다.
- [저장된 KiCad netlist](../netlist.xml): SEN1의 핀 목록을 확인했다. 이번 검사에서는 netlist를 새로 생성하지 않았다.
- [기계 판독 결과](source-audit.json): 원본 레코드·내부 줄 번호·좌표·거리·접촉 결과와 입력 파일 해시를 보존했다. 검사 전후 입력 파일 해시가 같음을 확인했다.
- 별도 라이브 확인 자료: [EasyEDA PCB 연결 목록](live-pcb-connectivity.json), [SEN1 강조 화면](easyeda-sen1-highlight.png). 아래 원본 아카이브 분석과 구분한다.

## 원본 회로도: 두 핀만 연결됨

아카이브 내부 파일은 `SHEET/dd2cfae3a64d4b3db5dd5a512ac44bc2/1.esch`다. 줄 번호는 내부 텍스트의 첫 줄을 1로 센 값이다.

| 근거 | 내용 |
|---|---|
| 401행 | `WIRE e335`: `(530,315) → (565,315) → (565,335) → (590,335)` |
| 402행 | 위 선의 `NET` 속성은 `SEN1` |
| 294–297행 | `(530,315)` 위치에 `SEN1` 이름표 |
| 178–186행 | `sensor1` 부품 `e1959`, 위치 `(610,335)` |
| 197–205행 | `10k` 부품 `e2154`, 위치 `(530,335)`, 회전 270도 |

부품 심볼의 핀 위치에 위 배치·회전을 적용하고 선과의 접촉을 다시 계산했다.

| SEN1 선에 닿는 부품 핀 | 회로도 좌표 | 심볼 내부 근거 |
|---|---|---|
| sensor1 2번 → KiCad J7.2 | `(590,335)` | `SYMBOL/d6537b7d0a3c4921a72c7e92ea99285b.esym` 13행 |
| 10k 2번 → KiCad R3.2 | `(530,315)` | `SYMBOL/1970f568a8d042eb887975c2466577d3.esym` 6행 |

전체 실장 부품의 52개 핀 중 이 두 핀만 SEN1 선에 닿는다. 다른 회로도 선과의 접촉은 없으며, MCU의 핀도 없다. 원본에는 회로도 시트가 하나다. 따라서 이름표를 통해 다른 시트의 MCU에 연결된 경우도 이 아카이브에서는 발견되지 않았다.

## 원본 PCB: 빈 net 이름의 MCU 패드에 닿는지도 확인함

아카이브 내부 파일은 `PCB/230020836b7d42a2ae0bd4e6ece12948.epcb`다.

| 근거 행 | 원본 기록 |
|---|---|
| 495, 505 | `e200`은 10k 저항, 2번 패드의 net은 `SEN1` |
| 511, 529 | `e204`는 sensor1, 2번 패드의 net은 `SEN1` |
| 569, 610–625 | `e216`은 Tenstar MCU 모듈. 16개 패드 중 SEN1은 없음 |
| 624, 625 | MCU 15·16번 패드의 net 이름은 빈 문자열 |
| 267–270 | SEN1 구리 트랙 네 개. 모두 아래 구리층, 폭 10mil = 0.254mm |

SEN1 트랙의 실제 경로는 다음과 같다. 좌표 단위는 원본 PCB의 mil이다.

```text
(1109.993,-1090) → (1125,-1074.993) → (1125,-965)
                → (1390,-700) → (1425,-700)
```

이 경로는 sensor1 2번에서 저항 2번으로 이어진다. 트랙의 중심선만 비교하지 않고 **트랙 폭과 패드의 구리 크기·회전까지 반영**했다. 전체 118개 트랙과 52개 부품 패드를 대조한 결과는 다음과 같다.

- SEN1 트랙이 닿는 부품 패드는 `e204.2`와 `e200.2`뿐이다.
- SEN1 트랙 또는 두 패드가 다른 net·빈 net 트랙이나 다른 부품 패드에 닿는 경우는 없다. 원본 비아는 0개다.
- SEN1 트랙과 가장 가까운 MCU 패드의 구리 사이에도 약 **6.765mm**가 남는다(U1.1).
- GPIO20에 해당하는 MCU 15번 패드와는 구리 사이 약 **22.184mm**가 남는다. 따라서 이 패드에 net 이름만 빠졌고 트랙은 닿아 있는 경우가 아니다.

| 대상 | 원본 PCB 좌표(mil) | KiCad 절대 좌표(mm) |
|---|---|---|
| sensor1 / J7.2 | `(1109.993,-1090)` | `(168.194,117.686)` |
| 10k / R3.2 | `(1425,-700)` | `(176.195,107.780)` |
| Tenstar / U1.15 | `(215,-760)` | `(145.461,109.304)` |

원본 풋프린트 `FOOTPRINT/c001ad73decd48a6aac368cc74cb7e4d.efoo` 156·157행에 MCU 15·16번 패드가 있다. 같은 풋프린트의 실크는 각각 `20`·`21`인데 회로도 심볼은 `GPIO21`·`GPIO22`다. 이 **이름 불일치**와 **SEN1 미연결**은 별개의 사실이다. 어느 이름을 적용해도 두 패드가 SEN1 구리에 닿지 않는 결과는 같다.

## KiCad 변환본: 원본과 같은 연결 상태

| 파일·행 | 확인 내용 |

| 같은 파일 3602–3608행 | J7의 2번 패드 = SEN1 |

KiCad의 실제 구리 도형 충돌 검사도 **접촉 패드 J7.2·R3.2만 존재, 다른 트랙·패드와 접촉 0**으로 나왔다. 위·아래 GND 구리 채움과 SEN1 트랙·패드의 접촉도 0이다. MCU 패드까지의 거리도 원본 계산과 반올림 범위에서 일치한다. 이 결과는 KiCad 변환 때 SEN1 연결을 잃었다는 설명을 지지하지 않는다.

## 이 증거가 말하지 않는 것

- **설계 상태:** 저장된 원본에 SEN1→MCU 신호 배선이 없다. 이것이 의도적인 미배선인지 설계 누락인지는 파일만으로 판단하지 않는다.
- **실물 상태:** 제작에 사용한 판본, 보드 뒷면의 납땜·추가 전선, 실제 패드 연속성·전압·센서 핀 순서는 측정하지 않았다. 실물에 별도 연결이 있다면 파일과 다를 수 있다.
- **변환 해석:** 현재 KiCad PCB를 직접 읽어 구리 접촉까지 검사했고 원본과 같은 결과다. 저장된 netlist는 보조 근거이며 이번에 재생성하지 않았다.
- **검사 한계:** 원본 EasyEDA 구리 채움의 `ARC` 도형 전체를 별도 구현해 계산하지는 않았다. 원본 채움의 net은 위·아래 모두 GND다. KiCad로 변환된 실제 채움 도형은 직접 접촉 검사했다.
- **오류 응답의 원인:** DHT `error`만으로 설계 누락이나 센서 고장을 증명할 수 없다. 이 문서의 결론은 오류 응답이 아니라 원본 레코드와 구리 기하 검사에 근거한다.

이번 작업은 설계 파일·보드·펌웨어를 변경하지 않고 증거 문서 두 개만 추가했다.
